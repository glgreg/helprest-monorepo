# API HTTP Interface (`helprest-api/src/interface`)

## Purpose and Design Decisions

Exposes the HelpRest REST API over **ElysiaJS** (`createApp()` in `src/app.ts`, started via `app.listen(PORT)` in `src/index.ts`). Global cross-cutting concerns live in composable plugins (`src/interface/plugins/`), while domain routes are isolated into factory-constructed feature modules (`src/interface/modules/*.module.ts`) with TypeBox / Zod v4 validation and Swagger OpenAPI documentation at `/swagger`. Legacy `src/interface/http/router.ts` and `middleware/` remain unused on disk after the ElysiaJS migration.

## Invariants

- **Mandatory NoSQL Input Sanitization (`securityPlugin`)**: `onBeforeHandle` sanitizes both `body` and `query` in-place via `sanitize()` (`@shared/utils/sanitize`) to strip keys starting with `$` before route handlers execute, while `onAfterHandle` attaches OWASP security headers (`X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `X-XSS-Protection`, and `Strict-Transport-Security` in production) and CORS headers.
- **Declarative Hierarchical RBAC (`authPlugin`)**: Protected routes use the `{ role: "user" | "establishment_admin" | "admin" | "superadmin" }` macro (with `@elysiajs/bearer` and `@elysiajs/jwt`), verifying the Bearer token and checking `Role.hasPermission(requiredRole)` (`401` when missing/invalid, `403` when insufficient).
- **Consistent Error Mapping (`errorPlugin`)**: Global `onError` maps `ValidationError` (including `details`), `AppError` subclasses, Elysia `VALIDATION` (`400`), `NOT_FOUND` (`404`), and unexpected errors (`500` logged without leaking stack traces).
- **Module Factory Injection**: Each module exports `create*Module(...)` accepting repository overrides so unit tests (`tests/unit/interface/`) can test routes via `app.handle(new Request(...))` without a live database.

## Integration Contracts

- **Entry Point**: `app` / `createApp()` exported from `src/app.ts` and mounted in `src/index.ts` (with graceful `SIGINT`/`SIGTERM` shutdown).
- **Endpoints**:
  - System & Docs: `GET /api/health`, `GET /swagger`
  - Auth (`auth.module.ts`, OAuth-only): `POST /api/auth/google`, `POST /api/auth/refresh`
  - Users (`user.module.ts`): `GET /api/users/me`, `PATCH /api/users/me`, `PATCH /api/users/me/flags`
  - Establishments (`establishment.module.ts`): `GET /api/establishments`, `GET /api/establishments/recommended`, `GET /api/establishments/nearby`, `GET /api/establishments/search`, `GET /api/establishments/my-establishment`, `GET /api/establishments/:id`, `POST /api/establishments`
  - Products (`product.module.ts`): `POST /api/products`, `PATCH /api/products/:id`, `DELETE /api/products/:id`
  - Flags (`flag.module.ts`): `GET /api/flags`, `GET /api/flags/admin/all`, `POST /api/flags`, `PATCH /api/flags/reorder`, `PATCH /api/flags/:id`, `DELETE /api/flags/:id`
  - Visits & Social (`visit.module.ts`): `POST /api/visits`, `POST /api/visits/:id/report`, `GET /api/visits/user/:userId`, `GET /api/visits/establishment/:id`, `GET /api/social/feed`
  - Favorites (`favorite.module.ts`): `GET /api/favorites`, `POST /api/favorites`, `DELETE /api/favorites/:id`
  - Admin (`admin.module.ts`, `role: "admin"`): `GET /api/admin/dashboard`, `GET /api/admin/visits/reported`, `PATCH /api/admin/visits/:id/moderate`, `GET /api/admin/users`, `PATCH /api/admin/users/:id/role`, `PATCH /api/admin/users/:id/ban`, `GET /api/admin/users/:id/history`, `GET /api/admin/audit-logs`

## Anti-Patterns

- Mounting new routes in legacy `src/interface/http/router.ts` instead of `src/interface/modules/*.module.ts` and `src/app.ts`.
- Bypassing `securityPlugin` or `authPlugin`'s `role` macro on protected endpoints.
- Returning raw `Error` stack traces to clients instead of throwing typed `AppError` subclasses handled by `errorPlugin`.
