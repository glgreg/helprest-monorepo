# API HTTP Interface (`helprest-api/src/interface`)

## Purpose and Design Decisions

Exposes the HelpRest REST API over `Bun.serve` without external web frameworks. `router.ts` compiles route patterns (`:param`) into regular expressions, wires singleton infrastructure repositories into per-request application use cases, validates inputs with Zod v4 schemas (`src/interface/validation/`), strips NoSQL injection operators (`$gt`, `$ne`, etc.), and attaches CORS, security, and `X-Request-Id` headers on every response.

## Invariants

- **Mandatory NoSQL Input Sanitization (`parseBody`)**: Every JSON request body must pass through `sanitize(raw)` (`@shared/utils/sanitize`) before Zod validation (`schema.safeParse`) to strip keys starting with `$`.
- **Route Registration Order (`addRoute` / `matchRoute`)**: `matchRoute` evaluates `routes` sequentially and returns the first regex match. Static sub-paths (such as `/api/establishments/recommended`, `/api/establishments/nearby`, `/api/establishments/search`, `/api/establishments/my-establishment`) must be registered **before** parameterized routes at the same depth (`/api/establishments/:id`) so `:id` does not capture literal segments.
- **Bearer Authentication (`authenticateRequest`)**: Protected routes must call `await authenticateRequest(req)` (`middleware/auth.middleware.ts`), which extracts the `Authorization: Bearer <token>` header, verifies it via `verifyAccessToken`, and returns `{ sub, email }` or throws `UnauthorizedError` (`401`).
- **Consistent Response Envelope & Headers (`handleRequest`)**: Every response (both success and error paths in `catch`) applies `applyCorsHeaders`, `applySecurityHeaders` (`HSTS`, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy`), and `X-Request-Id`.

## Integration Contracts

- **Entry Point**: `handleRequest(request: Request): Promise<Response>` exported from `src/interface/http/router.ts` and passed to `Bun.serve` in `src/index.ts`.
- **Endpoints Consumed by `app-services`**:
  - Auth: `POST /api/auth/register`, `POST /api/auth/login`, `POST /api/auth/refresh`, `POST /api/auth/google`
  - Users: `GET /api/users/me`, `PATCH /api/users/me`, `PATCH /api/users/me/flags`
  - Establishments: `GET /api/establishments`, `GET /api/establishments/recommended`, `GET /api/establishments/nearby`, `GET /api/establishments/search`, `GET /api/establishments/my-establishment`, `GET /api/establishments/:id`, `POST /api/establishments`
  - Products: `POST /api/products`, `PATCH /api/products/:id`, `DELETE /api/products/:id`
  - Flags: `GET /api/flags`, `POST /api/flags`
  - Visits & Social: `POST /api/visits`, `GET /api/visits/user/:userId`, `GET /api/visits/establishment/:id`, `GET /api/social/feed`
  - Favorites: `GET /api/favorites`, `POST /api/favorites`, `DELETE /api/favorites/:id`
  - Health: `GET /api/health`

## Anti-Patterns

- Reading `await req.json()` directly in a route handler without passing the payload through `sanitize()` and a Zod schema in `src/interface/validation/`.
- Registering `/api/establishments/:id` above static `/api/establishments/<subpath>` routes.
- Returning raw `Error` stack traces to the client instead of delegating to `handleError(error, requestId)`.
