# API Application (`helprest-api/src/application`)

## Purpose and Design Decisions

This layer orchestrates domain entities, domain services, and repository contracts to fulfill each application use case (`auth`, `user`, `establishment`, `product`, `flag`, `visit`, `favorite`). Use cases are lightweight classes instantiated per HTTP request with repository dependencies injected via their constructors, returning plain JSON-serializable DTOs rather than domain entities.

## Invariants

- **100-Meter Geofencing on Visit Photos (`CreateVisit`)**: If `input.photoUrls` is non-empty, `input.coordinates` must be present and within `100` meters of `establishment.location.coordinates` (verified via `RecommendationService.haversineDistance`). Requests without coordinates or beyond `100m` throw `ValidationError`.
- **Automatic Rating Recalculation (`CreateVisit`)**: Persisting a visit must atomically recalculate and persist the establishment's rating via `establishment.withNewRating(input.rating)` and `estRepo.update()`.
- **Establishment Admin Ownership (`CreateProduct`, `UpdateProduct`, `DeleteProduct`)**: Mutating a product requires verifying `establishment.adminId?.toHexString() === adminId`; mismatches throw `ForbiddenError` (`403`).
- **Product Ordering in Establishment Details (`GetEstablishment`)**: Products returned for an establishment are sorted with `isActive: true` items first, and then by `matchCount` descending (number of product flags matching the requesting user's dietary flags).
- **Google OAuth Server-Side Verification (`GoogleAuthUser`)**: Verifies the client's `googleIdToken` directly against Google's remote JWKS (`https://www.googleapis.com/oauth2/v3/certs`) using `jose.createRemoteJWKSet` and audience `GOOGLE_OAUTH_CLIENT_ID`, linking existing accounts by `googleId` or `email` and returning `{ accessToken, refreshToken, isNewUser, user }`.

## Integration Contracts

- **Constructor Injection**: Use cases accept domain repository interfaces (`IUserRepository`, `IEstablishmentRepository`, `IFlagRepository`, `IVisitRepository`, `IUserFavoriteRepository`, and `ProductRepository` in `src/application/repositories/ProductRepository.ts`).
- **DTO Outputs**: All `execute()` methods return plain objects with `ObjectId` values converted via `.toHexString()` and never expose `passwordHash`.
- **Error Signaling**: Domain/application failures throw typed `AppError` subclasses (`NotFoundError`, `ValidationError`, `UnauthorizedError`, `ForbiddenError`, `ConflictError`) caught by `api-http`'s error middleware.

## Anti-Patterns

- Returning `User` or `Establishment` entity instances directly from `execute()` without mapping to a DTO.
- Allowing product mutations without verifying `establishment.adminId` against the authenticated `auth.sub`.
- Bypassing the `100m` Haversine check when `photoUrls` are attached to a visit.
