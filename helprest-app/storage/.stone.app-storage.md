# App Storage (`helprest-app/storage`)

## Purpose and Design Decisions

Encapsulates synchronous, high-performance local persistence on the mobile device using `react-native-mmkv` instead of `AsyncStorage`. Isolated MMKV namespaces (`auth-tokens` in `authTokens.ts` and `user-profile` in `userProfile.ts`) store JWT session tokens, Google sign-in metadata, cached user/establishment profiles for offline fallback, and onboarding state.

## Invariants

- **Isolated MMKV Namespaces**: `authTokens.ts` uses `new MMKV({ id: "auth-tokens" })` and `userProfile.ts` uses `new MMKV({ id: "user-profile" })`. Clearing profile cache must not accidentally wipe tokens unless performing a full logout (`clearTokens()` + `clearUserProfile()`).
- **Atomic Token Pair Persistence (`saveTokens` / `loadTokens`)**: `loadTokens()` returns `{ accessToken, refreshToken }` only when **both** strings are present in MMKV; otherwise it returns `null`.
- **Onboarding Completion Rules (`getIncompleteOnboardingStep`)**: Inspects `CachedUserProfile` and returns step `1` if `name` is missing/blank, step `2` if `birthDate` is missing, step `3` if both `location.address` and `location.city` are missing, or `null` when mandatory onboarding fields are complete (step 4 dietary flags are optional).

## Integration Contracts

- **`authTokens.ts`**: `saveTokens(tokens)`, `loadTokens()`, `clearTokens()`, `isAuthenticated()`, `saveGoogleUserInfo(user)`, `loadGoogleUserInfo()`, `clearGoogleUserInfo()`, `clearAll()`.
- **`userProfile.ts`**: `saveUserProfile(profile)`, `loadUserProfile()`, `clearUserProfile()`, `getIncompleteOnboardingStep(profile)`, `saveCompanyOnboardingStatus(isCompany)`, `loadCompanyOnboardingStatus()`, `clearCompanyOnboardingStatus()`.

## Anti-Patterns

- Instantiating `new MMKV()` directly inside React screen components instead of calling functions in `helprest-app/storage/` or `helprest-app/utils/`.
- Using `storage/userLoginStatus.ts` (legacy/deprecated) for authentication guard checks instead of `loadTokens()` and `loadUserProfile()`.
