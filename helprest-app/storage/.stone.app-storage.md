# App Storage (`helprest-app/storage`)

## Purpose and Design Decisions

Encapsulates synchronous, high-performance local persistence on the mobile device using `react-native-mmkv` instead of `AsyncStorage`. Centralized key and instance definitions live in `storage/keys.ts` (`StorageKeys`, `StorageInstances`), isolating MMKV namespaces (`auth-tokens` in `authTokens.ts`, `user-profile` in `userProfile.ts`, and `app-state` in `userLoginStatus.ts`) for JWT session tokens, Google sign-in metadata, cached user/establishment profiles for offline fallback, and onboarding state.

## Invariants

- **Isolated MMKV Namespaces (`storage/keys.ts`)**: `authTokens.ts` binds to `StorageInstances.AUTH` (`"auth-tokens"`), `userProfile.ts` binds to `StorageInstances.USER_PROFILE` (`"user-profile"`), and `userLoginStatus.ts` binds to `StorageInstances.APP_STATE` (`"app-state"`). Clearing profile cache must not accidentally wipe tokens unless performing a full logout (`clearTokens()` + `clearUserProfile()`).
- **No Magic Storage Strings**: Every MMKV read/write/delete inside `storage/` must reference `StorageKeys` and `StorageInstances` from `storage/keys.ts`.
- **Atomic Token Pair Persistence (`saveTokens` / `loadTokens`)**: `loadTokens()` returns `{ accessToken, refreshToken }` only when **both** strings are present in MMKV; otherwise it returns `null`.
- **Onboarding Completion Rules (`getIncompleteOnboardingStep`)**: Inspects `CachedUserProfile` and returns step `1` if `name` is missing/blank, step `2` if `birthDate` is missing, step `3` if both `location.address` and `location.city` are missing, or `null` when mandatory onboarding fields are complete (step 4 dietary flags are optional).

## Integration Contracts

- **`keys.ts`**: `StorageKeys` (`AUTH`, `USER`, `ONBOARDING`) and `StorageInstances` (`AUTH`, `USER_PROFILE`, `APP_STATE`).
- **`authTokens.ts`**: `saveTokens(tokens)`, `loadTokens()`, `clearTokens()`, `isAuthenticated()`, `saveGoogleUserInfo(user)`, `loadGoogleUserInfo()`, `clearGoogleUserInfo()`, `clearAll()`.
- **`userProfile.ts`**: `saveUserProfile(profile)`, `loadUserProfile()`, `clearUserProfile()`, `getIncompleteOnboardingStep(profile)`, `saveCompanyOnboardingStatus(isCompany)`, `loadCompanyOnboardingStatus()`, `clearCompanyOnboardingStatus()`.
- **`userLoginStatus.ts`**: `saveUserLoginStatus(status)`, `loadUserLoginStatus()`, `clearUserLoginStatus()` (fast-path UI flag, not an auth guarantee).

## Anti-Patterns

- Instantiating `new MMKV()` with raw string IDs or raw key literals inside React screen components instead of calling functions in `helprest-app/storage/` backed by `storage/keys.ts`.
- Using `storage/userLoginStatus.ts` for authentication guard checks instead of `loadTokens()` and `loadUserProfile()`.
