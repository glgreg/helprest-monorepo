# App Components (`helprest-app/components`)

## Purpose and Design Decisions

Houses reusable visual building blocks for `helprest-app`, organized by Atomic Design levels so screens in `app-routing` compose UI without duplicating styling or layout logic:

- `atoms/` — Minimal display units (`MiddleDot`, `TextDistance`).
- `ui/` — Domain-aware UI primitives and composite widgets (`Card`, `CardHorizontal`, `FlagColoredText`, `HeartClicable`, `IconCircle`, `ImageRounded`, `ProductBottomSheet`, `ProfileSheet`, `StarReview`, `UserBar`).
- `login/` — Shared onboarding and authentication layout controls (`Container`, `LoginOption`, `NextButton`, `UserInput`, `UserProgress`).

## Invariants

- **Presentational Separation**: Components in `atoms/`, `ui/`, and `login/` receive data and callbacks via props (`Types.ts`) and do not perform direct `api` network calls or mutate MMKV stores directly (except interactive widgets explicitly wired to hooks like `HeartClicable`).
- **Dynamic Dietary Flag Styling (`FlagColoredText`)**: Dietary flag badges render their `tag`, `backgroundColor`, and `textColor` directly from the API's `FlagDTO` payload rather than hardcoding flag names or colors.

## Integration Contracts

- Shared prop interfaces are exported from `components/Types.ts` and individual component modules (`ProductBottomSheet`, `ProfileSheet`, `Card`, `CardHorizontal`, `UserBar`, `Container`, `UserInput`, `NextButton`, `UserProgress`).

## Anti-Patterns

- Hardcoding dietary restriction colors or labels inside UI components instead of consuming `FlagDTO` properties (`tag`, `backgroundColor`, `textColor`).
- Embedding screen navigation state machines or raw `fetch()` calls inside `components/atoms/` or `components/ui/`.
