# App Routing (`helprest-app/app`)

## Purpose and Design Decisions

Implements file-based navigation with Expo Router v5 across four route groups:

- `_layout.tsx` — Root `QueryClientProvider` and session/onboarding gatekeeper.
- `(auth)/` — Unauthenticated login (`home.tsx`), 6-step consumer registration (`register/step1..step6.tsx`), and 3-step establishment registration (`register-establishment/step1..step3.tsx`).
- `(app)/(tabs)/` — Consumer bottom tabs: `(home)` discovery/recommendations, `(places)` search & map/list, `(favorites)` saved establishments/products, and `(social)` community visit feed.
- `(app)/(establishment)/` — Establishment admin portal (`dashboard.tsx`, `menu.tsx`, `product-form.tsx`), plus modal/detail routes `details/[id].tsx`, `product/[id].tsx`, and `visit/create.tsx`.

## Invariants

- **Root Session & Role Routing (`app/_layout.tsx`)**:
  - On mount, `validateSession()` checks `loadTokens()`. Without tokens, it routes to `/(auth)/home`.
  - With tokens, it validates against `GET /api/users/me`, caches the profile via `saveUserProfile()`, and checks `getIncompleteOnboardingStep(profile)`. If incomplete (for consumer role), it redirects to `/(auth)/register/step<N>`.
  - When authenticated and complete, `profile.role === "establishment"` routes to `/(app)/(establishment)/dashboard`, whereas `"user"` routes to `/(app)/(tabs)/(home)`.
  - On network errors during startup, `_layout.tsx` attempts `POST /api/auth/refresh` before falling back to `loadUserProfile()` offline cache.
- **Client-Side Visit Photo Geofencing (`app/(app)/visit/create.tsx`)**: Before allowing a user to attach/submit visit photos, the screen checks device GPS coordinates against the establishment's coordinates (`100m` radius) to match the backend invariant in `api-application` (`CreateVisit`).

## Integration Contracts

- Consumes `api`, `signInWithGoogle`, and `getCurrentPosition` from `app-services`, token/profile helpers from `app-storage`, query hooks from `app-queries`, and UI primitives from `app-components`.

## Anti-Patterns

- Bypassing `_layout.tsx` session state by navigating directly to `/(app)/(tabs)` without persisting tokens via `saveTokens()` and profile state via `saveUserProfile()`.
- Routing establishment admin accounts (`role === "establishment"`) into consumer onboarding steps or consumer tabs without checking `profile.role`.
